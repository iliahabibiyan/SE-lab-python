# کنترل دسترسی پروفایل کاربران (US3، US4 و US5)

## نقش‌ها
هر کاربر ستون `users.role` دارد: `USER` (پیش‌فرض)، `ADMIN`، `MANAGER` (مدیر شعبه) یا `OFFICER` (مسئول انطباق). کاربر هنگام ثبت‌نام نمی‌تواند نقش خودش را تعیین کند (فیلد `role` در بدنه رد می‌شود).

## قواعد
| درخواست | USER | ADMIN |
| --- | --- | --- |
| `GET /api/v1/users/{id}` برای پروفایل خودش | 200 | 200 |
| `GET /api/v1/users/{id}` برای پروفایل دیگری | 403 | 200 (یا 404 اگر وجود نداشت) |
| `GET /api/v1/users` و جستجو با `national_code` | فقط رکورد خودش | همه‌ی کاربران |
| `PUT /api/v1/users/{id}` برای پروفایل خودش | 200 | 200 |
| `PUT /api/v1/users/{id}` برای پروفایل دیگری | 403 | 200 (یا 404 اگر وجود نداشت) |
| `PATCH /api/v1/users/{id}/status` | 403 | ADMIN، MANAGER و OFFICER: 200 (یا 404 اگر وجود نداشت) |

- بدون توکن همه‌ی این درخواست‌ها `401` می‌گیرند.
- کاربر عادی برای شناسه‌ی ناموجود هم `403` می‌گیرد (نه `404`)، تا نتواند وجود یا عدم وجود شناسه‌ها را حدس بزند.
- ویرایش فقط سه فیلد `phone_number`، `address` و `postal_code` را عوض می‌کند؛ بقیه‌ی فیلدها (کد ملی، نام، نقش، وضعیت، ...) در بدنه رد می‌شوند.
- نقش از دیتابیس خوانده می‌شود (نه از توکن)؛ پس تغییر نقش یا وضعیت کاربر فوراً اثر می‌کند.

## ساختن ادمین (برای تست و دمو)
هنوز endpointی برای تغییر نقش نداریم؛ ادمین مستقیماً در دیتابیس ساخته می‌شود:
```bash
docker compose exec db psql -U labbank -d s1_accounts -c "update users set role = 'ADMIN' where national_code = '0013542419';"
```

## تغییر وضعیت کاربر (US5)
- فقط `ADMIN`، `MANAGER` و `OFFICER` می‌توانند `PATCH /api/v1/users/{id}/status` را صدا بزنند؛ بقیه `403` می‌گیرند (حتی برای شناسه‌ی ناموجود).
- قاعده در یک جا (`app/permissions.py`: `STATUS_CHANGE_ROLES`) تعریف شده و با `require_roles` اعمال می‌شود.
- هیچ‌کس وضعیت خودش را عوض نمی‌کند (`409`).
- وضعیت حساب‌های کاربر با این endpoint تغییر نمی‌کند.

نقش‌ها هم مثل ادمین مستقیم در دیتابیس تنظیم می‌شوند:
```bash
docker compose exec db psql -U labbank -d s1_accounts -c "update users set role = 'MANAGER' where national_code = '<کد ملی>';"
```
